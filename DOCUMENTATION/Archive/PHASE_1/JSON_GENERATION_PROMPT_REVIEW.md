# JSON_GENERATION_PROMPT.md Review & Migration

## Current State

**File:** `backend/app/utils/diagram_wizard/prompts/JSON_GENERATION_PROMPT.md`

**Current Output:** Legacy JSON schema with metadata, components, connections, users

**Issues:**
1. ❌ Not aligned with new Structurizr-based system
2. ❌ Uses custom JSON schema (not Structurizr DSL)
3. ❌ Inconsistent with new ANALYSE_CONFIRM/CLARIFY_UNIVERSAL prompts
4. ❌ Doesn't match unified output contract

---

## Problem Analysis

### What This Prompt Does (Currently)

This prompt is called in the `generate_json_representation()` function in `nodes.py` to:
- Parse conversation history
- Create structured JSON representation of the architecture
- Output conforms to a legacy JSON schema

### Why It's Wrong Now

1. **Schema Mismatch:**
   - Current: Custom `metadata`, `components`, `connections`, `users` structure
   - Needed: Structurizr DSL format (`structurizr_workspace` + `clean_d2`)

2. **Not Model-Aware:**
   - No consideration for different LLM models
   - Should have 4 versions (GPT-5, Grok, Claude, Gemini)

3. **Duplicate Work:**
   - ANALYSE_CONFIRM already outputs Structurizr
   - CLARIFY_UNIVERSAL already outputs Structurizr
   - This prompt shouldn't need to re-generate—it should refine existing Structurizr

4. **Flow Issues:**
   - Current flow: analyze_request → clarify_prompt → **generate_json_representation** → generate_code
   - **Problem:** generate_json_representation runs AFTER clarify_prompt completes
   - **Better:** use the `clean_d2` already generated by clarify_prompt

---

## Recommended Solution

### Option A: Replace with Structurizr Generator (Recommended)

**What:** Update JSON_GENERATION_PROMPT to output **Structurizr DSL** instead of custom JSON

**Benefit:** Aligns with ANALYSE_CONFIRM and CLARIFY_UNIVERSAL

**Files to Update:**
1. `JSON_GENERATION_PROMPT.md` → Structurizr DSL format
2. Create 4 model-specific versions (like ANALYSE_CONFIRM)

### Option B: Remove This Prompt Entirely

**What:** Delete this prompt and use `clean_d2` from clarify_prompt state

**Benefit:** Eliminates redundant LLM call, saves tokens

**Risk:** May miss refinements needed after clarification loop ends

**Recommendation:** Only if flow is re-architected
