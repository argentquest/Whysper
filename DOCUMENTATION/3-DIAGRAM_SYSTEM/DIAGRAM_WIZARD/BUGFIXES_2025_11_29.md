## Bug #1: Diagram Type Selection Not Working

### Problem Description
When users selected a diagram type (Mermaid, D2, PlantUML, or Structurizr) from the DiagramTypeSelectionScreen, the workflow would not proceed to code generation. The graph would terminate instead of routing to the `generate_code` node.

### Root Cause
The `determine_diagram_type_node` function was **always** returning `user_selected_diagram_type: False`, even after the user had selected a type. This happened because:

1. User clicks on diagram type
2. `select_diagram_type()` sets `user_selected_diagram_type: True` in state
3. Graph resumes and runs through `determine_diagram_type_node` again
4. **BUG:** Node overwrites the flag back to `False` (line 274)
5. Router sees `False` and routes to `END` instead of `generate_code`

### Location
**File:** `backend/app/utils/diagram_wizard/nodes/generation_nodes.py`
**Function:** `determine_diagram_type_node()`
**Line:** ~274 (before fix)

### Fix Applied
Added early return logic to preserve the user's selection:

```python
async def determine_diagram_type_node(state: GraphState) -> Dict[str, Any]:
    session_id = state.get("_session_id")

    # Check if user has already selected a diagram type (resuming after selection)
    if state.get("user_selected_diagram_type", False):
        logger.info("✅ User has already selected diagram type, proceeding to code generation...",
                   extra={'session_id': session_id} if session_id else {})
        # Return existing state values without changing anything
        return {
            "keyword_scores": state.get("keyword_scores", {}),
            "user_selected_diagram_type": True,  # Keep the selection flag
            "analysis_text": state.get("analysis_text", ""),
            "json_generation_output": state.get("json_generation_output", ""),
            "current_state": SessionState.GENERATING
        }

    # Continue with normal diagram type analysis...
```

### Testing
- ✅ User can select diagram type
- ✅ Workflow proceeds to code generation
- ✅ SVG renders successfully

## Bug #2: SVG Not Displaying in Frontend

### Problem Description
Even when diagram code was successfully generated and rendered to SVG on the backend, the SVG would not appear in the frontend's Preview tab. The browser console showed no SVG data being received.

### Root Cause
The `_run_graph_workflow()` method in DiagramFactoryService had an early return that prevented session state from being updated:

```python
result = await self.graph.ainvoke(initial_state)

# Check if the result is the end of the graph
if result.get("message") == "__end__":
    await self._push_update({
        "status": "completed",
        "message": "Diagram generation completed",
        "message_role": "assistant"
    })
    return  # ❌ Returns WITHOUT setting session.svg_output!

self.session.graph_state = result
self.session.diagram_code = result.get("diagram_code", "")
self.session.svg_output = result.get("svg_output", "")  # Never reached!
```

Since the graph ends with `workflow.add_edge("render_diagram", END)`, the `__end__` condition was always true after rendering, causing the early return before `session.svg_output` could be set.

### Location
**File:** `backend/app/services/diagram_factory_service.py`
**Function:** `_run_graph_workflow()`
**Lines:** ~397-411

### Fix Applied
Reordered the logic to update session state BEFORE checking for `__end__`:

```python
result = await self.graph.ainvoke(initial_state)

# Always update session with latest results first
self.session.graph_state = result
self.session.diagram_code = result.get("diagram_code", "")
self.session.svg_output = result.get("svg_output", "")

# Check if the result is the end of the graph
if result.get("message") == "__end__":
    await self._push_update({
        "status": "completed",
        "message": "Diagram generation completed",
        "message_role": "assistant"
    })
    return
```

## Enhancement: Async Provider System

### Problem Description
D2 diagram rendering can take 30-90 seconds when LLM-based correction is enabled. The original provider system was synchronous, which would block the event loop during long operations, preventing real-time progress updates and degrading server performance.

### Motivation
1. **User Experience:** Need real-time progress updates during long LLM operations
2. **Server Performance:** Cannot block event loop for 30-90 seconds
3. **Scalability:** Support concurrent diagram generations without blocking

### Changes Made

#### 1. Made Provider Core Methods Async

**File:** `backend/diagrams/base_diagram.py`

```python
# Before: Synchronous
def render_with_validation(self, code: str, ...) -> RenderResult:
    result = self.validate_code(code)
    if not result.is_valid:
        result = self._attempt_llm_correction(...)
    return self.render(code, output_format)

# After: Asynchronous
async def render_with_validation(self, code: str, ...) -> RenderResult:
    await self._send_progress(progress_callback, {
        "status": "validating",
        "message": "Validating code...",
        "step": "1/4"
    })

    result = self.validate_code(code)

    if not result.is_valid and llm_correction:
        await self._send_progress(progress_callback, {
            "status": "llm_correcting",
            "message": "Attempting AI correction...",
            "step": "3/4"
        })
        result = await self._attempt_llm_correction(...)

    await self._send_progress(progress_callback, {
        "status": "rendering",
        "message": "Rendering to SVG...",
        "step": "4/4"
    })

    return self.render(code, output_format)
```

#### 2. Added Progress Callback Support

**Progress Updates Sent:**
- **Step 1/4:** "Validating {diagram_type} code..."
- **Step 2/4:** "Attempting pattern-based auto-fix..." (if needed)
- **Step 3/4:** "AI correction attempt {N}/{max_retries}..." (if needed, with retry count)
- **Step 4/4:** "Rendering {diagram_type} to SVG..."
- **Complete:** "✅ {diagram_type} rendered successfully"

**Implementation:**

```python
async def _send_progress(
    self,
    progress_callback: Optional[Callable[[Dict[str, Any]], Awaitable[None]]],
    update: Dict[str, Any]
):
    """Send progress update via callback if provided."""
    if progress_callback:
        await progress_callback(update)
```

#### 3. Updated All Callers

**Rendering Node:**
**File:** `backend/app/utils/diagram_wizard/nodes/rendering_nodes.py`

```python
# Before: Synchronous call
result = provider.render_with_validation(
    code=diagram_code,
    output_format="svg",
    auto_fix=False,
    llm_correction=False
)

# After: Async call with progress callback
result = await provider.render_with_validation(
    code=diagram_code,
    output_format="svg",
    auto_fix=False,
    llm_correction=False,
    progress_callback=update_callback  # Pass SSE callback for real-time updates
)
```

**Diagram Provider Endpoint:**
**File:** `backend/app/api/v1/endpoints/diagram_provider.py`
